スクリーンショットの API キーを隠す方法

最終更新: 2026年11月14日

結論: スクリーンショットの API キーは、ブラウザ内で文字を読み取って（OCR）該当行を黒塗りすれば、 画像をどこにも送信せずに消せます。rm は API キー・トークン・パスワード・秘密鍵・ローカルパスを 候補として枠で示し、確認して保存するまでを 1 ページで行えます。

1. 手順（5 ステップ）

  1. https://rm.okamomedia.tokyo/ を開きます（インストール・会員登録は不要）。
  2. スクリーンショットをドロップ、または Ctrl+V で貼り付けます。
  3. 「検出方法」が ブラウザ内（無通信） になっていることを確認し、「文字も検出（OCR）」にチェックを入れます。
  4. 「この写真を検出」を押すと、機密らしい文字列の行が枠で示されます。
  5. 枠を確認し、不要な枠は Delete、足りない場所は矩形ツールで追加します。「隠し方」を黒く塗りつぶしにして「マスクして保存」を押します。

「この写真は確認済み」にチェックしていないまま保存しようとすると、目視確認を促す警告が出ます。 自動検出は候補を出すだけで、最終的な確認は人（あなた）が行う設計です。

2. 検出できる文字列

OCR で読み取った行に正規表現を当て、当てはまった行をマスクします。 代表的なものは次のとおりです（例はすべて伏せ字・予約済みの値です）。

種類例補足
API キー・トークン OPENAI_API_KEY = ... の値 主要サービスの接頭辞つきの文字列、JWT、32 文字以上のランダムな文字列
パスワード・秘密鍵 PASSWORD=...、-----BEGIN ... PRIVATE KEY----- 代入行の値。伏せ字や ${...} は対象外
メールアドレス user@example.com —
IP アドレス・認証つき URL 192.0.2.10、https://user:pass@host 内部 URL・接続文字列を含む
ローカルパス・端末プロンプト /home/user/project、user@host:~/dir$ command プロンプトだけの行（コマンドなし）は対象外

3. API キーは「黒塗り」を使う

モザイクやぼかしは元の画素情報を弱めるだけで、強度が低いと復元・推測の対象になります。 API キーやパスワードなど、漏れると取り返しがつかない情報は黒塗り（塗りつぶし）を使ってください。 rm の自動検出は、機密文字列に対して黒塗りを初期値として適用します（顔とナンバープレートはモザイク＋ぼかし）。

4. 検出できない（苦手な）パターン

  • 極端に小さい文字、強いぼけ、低コントラストの文字
  • 傾きや変形が大きい画面、反射やモアレのある撮影
  • 文字ではなく画像として貼り付けられたスクリーンショット
  • OCR の誤認識で文字の一部が欠けている行

自動検出に頼らず、手動の矩形も併用してください。とくに公開範囲の広い記事や資料では、 保存前の目視確認を必ず行ってください。

5. EXIF（GPS・撮影日時）も一緒に消える

書き出しは Canvas で JPEG を作り直すため、撮影場所（GPS）・撮影日時・機種名などのメタデータは残りません。 実測では、GPS 付きの JPEG を入力した場合に exif=true, gps=true が exif=false, gps=false になります。 Safari（iPhone）では、色空間（sRGB）と画素サイズだけを含む最小の Exif が付きますが、 位置情報・撮影日時・機種名は含まれません（node scripts/check-exif.mjs で確認できます）。

6. よくある質問

画像はサーバーに送信されますか？

送信されません。検出もマスクも書き出しもブラウザ内で完結します。 通信先は CSP（connect-src）で localhost に限定しているため、外部のサーバーへ画像を送ることはできません。

無料ですか？

無料です。MIT ライセンスでソースコードも公開しています。

元の画像は上書きされますか？

上書きされません。保存すると新しいファイルとして書き出されます。

アクセスログは残りますか？

静的ファイルの配信基盤には、一般的なウェブアクセスと同様に IP アドレス・ユーザーエージェント・URL などの 運用ログが残る場合があります。画像の中身や編集内容は含まれません。詳細は プライバシーポリシー をご覧ください。
